# 文档处理 v2

新上传文档使用 `app/document_pipeline.py`。PostgreSQL 新增独立的
`document_parses` 表，应用原有 `init_database()` 会通过 `create_all` 建表；
不修改已有 documents 列或 Milvus Collection，不需要删除已有数据库。

## 行为

- PDF 按页提取文本并对可疑图片页调用 OCR。OCR 失败会让上传失败，不再把部分页面当作完整文档。
- 空白页不强制 OCR。规则是启发式检测，复杂多栏、矢量文字和图片表格仍需人工抽样。
- DOCX 保留正文中段落/表格顺序；表格各行附带首行信息。
- XLSX 默认每个工作表的首个非空行为表头，一行一条记录，空单元格不改变列映射。
  无表头、复杂合并表头的文件应先整理为单行表头；公式使用 Excel 缓存值。
- 根据原文标题划分父章节。简历可识别“项目名称：…”等边界；无明确标题的项目不会自动猜测。
- 子块优先在句子、换行处切分，超长单句才按字符兜底；只在同一父块内重叠。
- FAQ 长答案的子块重复标准问题。保存章节、顺序、页码范围、工作表、行号。
- 标准全文、结构和分块结果持久化；分析时复用它们，不重复进行 OCR。
- 混合检索返回 `chunk_metadata` 和 `parent_context`。后者对不超过 2400 字符的父块
  扩展上下文，否则保留命中的子块。现有 `content` 字段不变；调用方使用父上下文时
  应按 `(document_id, parent_id)` 去重。
- BGE 以真实 tokenizer 为准拆分长候选，窗口最大分作为候选重排分。
  查询超过预留预算时截短；长候选会增加推理次数，日志会记录候选数与窗口数。
  此策略需要用真实问题评测，最大窗口分可能偏向长文档。

## 旧数据

重启后旧索引仍可查询。第一次读取没有缓存的旧文档时，生成并保存标准全文，
不自动重新嵌入、不修改原向量；因此旧索引不会自动获得新版分块和来源元数据。
要更新某个旧文档索引，可先保存原文件，再通过现有文档管理删除该文档并重新上传。
这会产生新的 document_id，引用旧 ID 的任务不会自动迁移；已有分析结果应保留。
不要直接删 Milvus Collection。相同文件、相同类型的 ready 文档仍会触发去重。

## 验证

在 backend 目录使用项目环境执行：

```bash
python -m unittest discover -s tests -v
```

测试使用合成 DOCX、XLSX、混合 PDF 和模拟 OCR，不访问云模型或运行中的数据库。
另外可用本地 BGE tokenizer 验证窗口预算，不需要加载模型权重。

真实效果评测应固定 Embedding、召回数量、重排参数，对同一组问题记录正确证据
Hit@5、重排前后排名、引用页码、延迟和窗口数量。新旧分块的 chunk_id 不相同，
标注应基于原文证据/来源位置，而不是复用旧 chunk_id。
