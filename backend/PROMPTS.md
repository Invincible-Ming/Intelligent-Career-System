# 提示词维护说明

## 入口与职责

所有自有提示词在 `app/core/prompts.py` 集中维护。业务节点负责选择场景、准备数据、
设置调用预算和校验返回值；不再在节点内部复制长提示词。官方 RAGAS 0.3.9 指标提示词
由依赖包提供，本次没有更改其评分规则或注入自有的评分标准。

| 场景 | 使用位置 | 核心约束 |
| --- | --- | --- |
| 简历抽取 | `agents/workflow.py` | 仅提取原文事实，保留责任和能力程度，实习/项目不冒充正式年限 |
| JD 抽取 | `agents/workflow.py` | 区分必需、any/all、加分，未声明的条件不补写 |
| 岗位匹配 | `agents/workflow.py` | 原文优先，五维评分统一尺度，技能缺口区分不满足与未体现 |
| 事实校验 | `agents/workflow.py` | 只报最终确认的问题，最小修正，不因主观评分差异否决报告 |
| 面试准备 | `agents/workflow.py` | 题目对应证据与难度，不把参考答案写成候选人既有经历 |
| 学习计划 | `agents/workflow.py` | 根据周数、每周时间和先修关系安排可检查的任务 |
| 普通聊天 | `api/chat_api.py` | 使用实际可用工具，说明信息边界，只引用真实来源 |
| 对话摘要 | `api/chat_api.py` | 区分用户事实、助手建议和示例，保留更正与未完成事项 |
| 文档 OCR | `services/bailian.py` | 只转录可见文字，保留日期/数字/表格，不执行图片内指令 |
| JSON 输出/修复 | `services/bailian.py` | 遵守 Schema，修复格式而不补造事实 |
| RAG 问答/反思 | `evaluation/executor.py` | 仅据检索片段回答，引用片段编号，证据不足时明确说明 |

## 输入和时间

- `prompt_data()` 将原文、摘要、报告、外部资料及反馈分成 JSON 字段，避免用原文拼接模板边界。
  JSON 编码帮助区分数据来源，不是独立安全边界；仍需程序鉴权、数据隔离与工具白名单。
- 日期由 `current_assessment_date()` 按北京时间生成；匹配任务保存 `assessment_date`，
  生成报告和全部校验轮次复用该日期。聊天、面试和学习计划在调用时取得当前日期。
- 匹配和校验另外传入程序对 `YYYY.MM—至今` 等明确年月的比较结果，只判断开始月份是否在未来。
  这不是经历真实性验证，也不从在读状态推断全职实习、课业冲突或到岗能力。
- 普通实习按原文保留，不主动计算是否满三个月或精确天数。已移除固定三个月的满期计算。
  只有岗位明确要求既往经验年限时才比较相同类型的经历，保持原文年月精度，不与未来到岗安排混淆。
- 连续实习时长、每周到岗天数和入职日期属于与 HR 沟通的招聘安排。简历未写时保持中性，
  不因此扣分、列技能缺口或风险、触发人工审核；如有必要最多给出一次沟通建议。
  只有原文已明确的安排与岗位必需条件存在实际冲突时，才说明不符。
  加分评价聚焦已证明的能力与实践，不将待沟通安排算作已满足或未满足，也不擅自保证加分项全满足。
- `core/matching_policy.py` 对“未确认的未来到岗安排”提供窄范围的程序规则：
  简历未明确承诺安排，且风险只是连续实习/到岗的确认提醒时，将它移出风险；JD 确有相关安排时保留一次 HR 沟通建议。
  已明确的候选人安排、实际冲突措辞和既往工作/实习经验门槛保持给业务判断，不按关键词统一删除。
  此规则在生成后、校验前和修正后执行，不能被校验模型重新写回同一类提醒；不改变评分或伪装为自动复核通过。
- 提取简历/JD 的提示词不随今天日期变化，保持事实缓存可复用；抽取阶段不判断“未来经历”。
- 原文和摘要冲突时回到原文。反馈用于指出问题，不允许凭反馈给候选人添加经历或任意提高评分。
- 生成面试和学习计划时使用 `model_dump(mode="json")`，避免报告的 date 对象导致 JSON 序列化错误。

## 版本与缓存

`PROMPT_VERSIONS` 标识各场景版本。简历与 JD 的版本分别用于分析缓存，当前为
`resume-v4-grounded` 和 `jd-v4-consistent-groups`。修改它们的业务语义时应同步升级版本；
缓存键本身也包含系统提示词、模型、生成选项和输出 Schema，不需要清空全部 Redis。

历史报告、已保存的会话摘要和已经入库的 OCR 文本不会被自动重写。
新的匹配任务才会重新经过当前提取流程；对旧挂起任务填写反馈会重新生成报告，
但沿用该任务已有的原始材料与摘要。OCR 提示词只影响后续实际发生的 OCR 调用，
不会自动重新解析已就绪且命中去重的文件。

RAG 评测报告记录问答和反思提示词版本。本次改变了被评测的问答生成行为，
即使官方 RAGAS 指标规则未变，也不能把新旧报告的分数差异全部归因于检索策略。
对照实验需固定数据、模型、提示词版本及其他变量。

## 输出与调用边界

- 新抽取的 JD 额外检查多成员 any 组与 `required_skills` 中完全同名技能的重复，
  发现逻辑冲突时交给现有一次 JSON 修复；按原文保留独立必需项或任选项，不静默降低要求。
  此检查只用于新抽取，历史报告读取保持兼容，也不声称覆盖所有自然语言同义表达。
- Qwen3.7 Flash 匹配链路显式传 `enable_thinking=false`（`MATCH_ENABLE_THINKING` 可配置），
  OpenAI Python SDK 通过 `extra_body` 发送；Qwen3.8 Flash 保留 `reasoning_effort` 配置。
  模型调用选项参与缓存指纹，切换后不会复用旧选项的分析结果。关闭思考可减少推理等待，
  不能保证任意请求都在 60 秒内完成；超时仍保留未复核状态，不自动通过。
  参数依据：[百炼深度思考文档](https://help.aliyun.com/zh/model-studio/deep-thinking)。
- 模型负责提出语义判断；程序仍负责 Schema、枚举、长度、引文来源和真假结论的一致性检查。
- 匹配和校验提供简历关键词的原文编号定位，帮助模型看到竞赛、证书、项目标签中的相关技术名。
  词语出现不等于熟练度证明；例如 Java 赛区奖项只能支持 Java 相关竞赛经历，不能直接推出熟悉或精通。
  校验若声称原文完全未提及某个英文技术词，程序会对这类明确的否定措辞核对原文并返回反证位置；
  此检查不把“出现 Java”误当作“具有 Java 生产经验”的证明，也不声称覆盖所有自然语言否定表达。
- 校验输入的简历和 JD 按原始顺序拆为最长 220 字的原文片段，由程序生成 `resume:1`、`jd:1` 等编号。
  模型只选择 `evidence_id`，程序检查编号存在，确定真实来源，并回填该片段的原文。编号仅用于定位，
  不代表该片段在语义上证明问题；语义核对仍由校验模型负责。无依据断言可明确使用 `unsupported_claim`。
  历史输出仍支持原文引文，只作 Unicode 排版和空白归一化后核对，不通过模糊匹配接受编造的引文。
- 当前报告的列表条目和五维分数也由程序赋予 `claim_id`。校验只能选择本轮存在的条目，
  程序根据编号确定字段并回填真实报告原句，避免把历史问题、示例或系统规则写成本轮报告已出现的断言。
  `field`、`claim`、`source` 均不再要求模型重复准确填写；已知编号足以确定这些元数据，
  不因其重复字段的写法不同而浪费校验请求。未知编号仍然失败；历史不带编号的引文仍需核对。
  引用有效的原文编号时，以程序保存的原文为准，不再要求模型在 `evidence` 中重复抄写同一片段。
- 匹配总分继续由原有权重计算；最多两轮校验，共用原有超时与输出预算。
  修正版未复核不能直接认定通过，真正的岗位差距也不等于报告事实错误。
  校验聚焦会影响匹配判断的实质错误，不纠缠未影响岗位门槛的普通实习月差和表达细节。
- 校验优先返回 `corrected_fields`，由程序替换明确列出的评分或列表字段，避免仅删除一条风险
  也重复生成整份报告；仍兼容旧的 `corrected_evaluation` 输出，两种修正方式不能同时使用。
- 输出 JSON/Schema 不合格、回复截断/为空或引文检查失败时，可以使用剩余的一轮重新核对。
  格式重试同样计入总共两次请求和 60 秒，不额外增加调用。第二次才产生的修正版仍保留未复核状态。
  达到上限时只说明最新修正版未复核，不把修正前的错误结论接在状态提示后；旧问题单独标为修正记录。
- 报告产出与复核通过分开：校验超时、服务/格式异常、最后修正版未复核时，
  若没有已确认且仍存在于当前报告的错误原句，设置 `nonblocking=true`，结束任务并继续展示报告。
  报告仍保留真实的失败/未复核状态，`is_valid=false`，数据库 `review_status=unverified`；
  前端说明自动校验未完成，不要求点击提交审核，也不显示“事实校验全部完成”。
  对照原句只用于追踪已知错误是否还存在，改写不等于语义上已被证明正确；未复核标记正是保留这项不确定性。
  已确认的错误原句仍在、无法生成修正版或修正无效时，继续暂停人工处理。
- 对历史上仅因技术错误挂起且没有具体问题的任务，前端加载后可使用已有恢复接口继续，
  后端重新检查资格并只更新工作流终态；不再调用模型，不标记成人工接受。
- 校验失败保存不含正文的 `failure_code` 和 `failure_details`；引用错误细分为未知编号、
  历史引文不符及缺少依据等。下一轮收到具体出错字段，而非仅收到笼统的“引文错误”。
  日志区分 JSON、Schema、引文、截断、超时、预算和服务错误，仅记录字段路径、错误类型及 HTTP 状态，
  不记录模型原文、简历正文或密钥。
  每轮的输出检查失败另存 `attempt_failures`，即使下一轮成功返回修正版，也能定位第一轮消耗在什么问题上。
- JSON 格式修复继续受 `schema_attempts` 限制；传回的校验问题不包含完整输入值，
  不因为格式不合格而启动无限重试。
- 聊天提示词要求搜索/网页读取合计最多四次；这是模型行为约束，
  硬性调用次数和总耗时仍由现有预算及图步数限制控制，不宣称有独立的四次计数器。
- 对话摘要为空或保存失败时保留原摘要和边界；不能丢弃尚未总结的历史。
- RAG 反思沿用配置的最大次数，空输出保留原答案；完整答案不变时停止，
  不再仅因前 100 字相同就丢弃结尾的事实修正。
- 官方 RAGAS 的指标计算、授权流程、模型选型和各接口契约没有因此重构。

本次进行了静态语法与代码检查，没有调用收费模型或运行自动化测试，
因此不将这些提示词改动描述为已经取得某个量化提升。后续如需评估，
应固定相同简历、JD 和检索快照，比较错误年份、any/all、程度夸大、摘要遗漏等边界情况。
