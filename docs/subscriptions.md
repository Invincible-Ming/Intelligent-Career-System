# 积分与检索方式（替代原订阅方案）

当前采用 `KNOWLEDGE_PROVIDER=credits`，不再按订阅等级分配功能。已有订阅和开通审计保留，
主应用不再注册订阅修改接口，页面改为「我的积分」。原文件名保留，方便已有链接继续访问。

## 默认规则

- 每个账号赠送 100 分；新账号注册时发放，已有账号首次查询或调用时补发，只发一次。
- 每天签到领取 10 分，按北京时间自然日判断；重复或并发签到只发一次，不支持补签。
- 输入与输出合计每 1000 Token 消耗 1 分。使用整数存储，1000 个单位等于 1 分，显示精度 0.001 分。
- 对话、内部意图识别和摘要、岗位分析/报告/校验、面试与学习计划、OCR、Embedding 均计入。
- 命中缓存而未再次请求模型的步骤、本地解析、BM25 与本地 BGE 重排序不扣分。
- 管理员同样消耗积分；原来的频率、并发、调用次数和耗时限制独立保留。
- 当前仅赠送和签到，不支持在线充值、现金兑换或自动续费。

在 `backend/.env` 可覆盖规则（不需要填写任何支付密钥）：

```dotenv
KNOWLEDGE_PROVIDER=credits
CREDITS_INITIAL_POINTS=100
CREDITS_DAILY_CHECKIN_POINTS=10
CREDITS_UNITS_PER_TOKEN=1
```

`CREDITS_UNITS_PER_TOKEN` 是每 Token 扣除的整数单位，也就是每千 Token 消耗的积分数。
修改初始赠送值不会重置已有钱包；费率在预留时写入流水，配置变化不会改变已开始调用的价格。
修改配置后重启后端。启动会自动新建钱包、流水和检索偏好表，原文档与任务不删除。

## 结算与边界

1. 登录身份确定扣费账号，客户端不能提交余额、费率或扣费用户。
2. 每次实际模型请求先锁定钱包并预留输入估算和输出上限，余额不足返回 HTTP 402；SSE 已开始则发出错误事件。
3. 服务商返回 `usage` 后按实际输入/输出 Token 结算，未使用的预留退回；推理 Token 若已包含在输出中不重复累计。
4. 未返回 `usage`，但调用完成或已收到部分输出时，按 UTF-8 字节和消息开销保守估算，并在明细标注「估算」。这不是供应商精确 tokenizer。
5. 没有取得用量或输出的失败请求释放预留，不扣分；多步骤任务中已经发生的调用仍扣分。
6. 同一调用流水只结算一次；实际用量超出本次预留时只扣预留上限，保留完整 Token 统计并标注上限。
7. 流式中断会尽力完成结算。进程崩溃留下的预留到期后，在下一次钱包查询/预留时释放；没有持久化的供应商用量不能声称精确对账。

预留用 UTF-8 字节做保守估算；OCR 图片每张另预留 16384 输入 Token。
因此长资料或并行调用所需的临时可用余额可能明显大于最终扣分。账本只记录用量与操作类型，不保存提示词、资料正文或密钥。

钱包和流水存 PostgreSQL，Redis 仍用于缓存，不能修改 Redis 来增加积分。

## 知识库自行选择

所有账号都可在「知识库 → 知识库检索方式」选择：

| 方式 | 检索内容 |
|---|---|
| ima + 本地关键词（默认） | 配置的 ima 共享库，加上当前用户私人文件的本地关键词匹配 |
| 混合检索 + 重排序 | 当前用户已完成索引的本地文件：Milvus 语义 + BM25 → RRF → BGE 重排序 |

ima 中的资料不会自动同步到本地向量库，本地上传也不会发布进共享 ima。
切换到混合检索会后台为旧文件准备索引，所需 Embedding 用量计入该文件所有者的积分。
积分不足或模型/向量服务异常会标记索引失败，签到后可以手动重试；失败/未完成索引不参与检索。
切回 ima 不会删除文件或已建立的向量，后台不会继续领取该账号的新索引任务；已经发出的模型调用仍结算。
旧文件的相同索引与 Embedding 缓存可以复用，不重复调用模型的步骤不扣分。

岗位匹配仍直接使用所选简历与 JD 正文，不是拿知识库检索相似度当匹配分数。

## 接口与部署

- `GET /api/credits/me`：余额、预留、可用积分、今日签到状态和规则。
- `POST /api/credits/check-in`：领取当天积分，不接受客户端指定日期或奖励。
- `GET /api/credits/entries?offset=0&limit=20`：仅本账号流水，最多每页 100 条。
- `PUT /api/knowledge/provider`：`{"provider":"ima"}` 或 `{"provider":"milvus"}`，仅修改本人偏好。
- `GET /api/auth/me`：包含积分信息和服务端选择的检索方式。
- `/pricing`：原价格链接改为积分规则页，规则数值由后端配置生成。

用户可切换两种检索时，需保留 PostgreSQL、Redis、MinIO、文档沙箱 Runner，
以及 Milvus 及其 etcd/MinIO 依赖；同时配置 ima。只启用固定 `ima` 部署时不必运行 Milvus。
命令行评测和健康探针属于维护调用；未绑定用户的维护请求不分配扣费账号。
